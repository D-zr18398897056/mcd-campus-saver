# M1 校园门店雷达

输入学校名 / 校区 / 地标，输出附近麦当劳门店，标注最近的一家，并挂上当月的活动标签。

---

## 1. 输入

| 输入项 | 是否必需 | 说明 |
|---|---|---|
| 位置关键词 | 是 | 学校名、校区名、地标，如「武汉大学」「松江大学城」「XX 大学南门」 |
| 城市 | 是 | `searchType=2` 时接口必填 |
| 取餐方式 | 是 | 决定 beType：步行/骑车/到店 → 1；开车/打车/得来速 → 5 |

---

## 2. 工具链

```
① （可选）now-time-info()
   → 确认当前时间，用于判断营业状态与活动是否在进行中

② query-nearby-stores(
     searchType = 2,               // 必填，2=按位置搜索；1=搜收藏餐厅
     city       = <城市>,          // searchType=2 时必填
     keyword    = <学校名/地标>,    // searchType=2 时必填
     beType     = 1 | 5            // 必填
   )
   → 返回门店列表，取 storeCode（beType=5 时还要取 beCode）

③ （可选）campaign-calendar()
   → 给最近门店挂上当月活动标签
```

### 参数取值规则

- `searchType` 固定传 **2**（按位置搜索）。
  `searchType=1` 是搜用户收藏餐厅，若无收藏记录会无结果，不适合校园场景。
- `beType` 由用户取餐方式决定：
  - 「走去 / 骑车去 / 到店吃 / 食堂旁边那家」→ **beType=1**（到店自取）
  - 「开车去 / 打车去 / 得来速 / 不下车取」→ **beType=5**（车道取餐）
- 用户说「送到宿舍 / 外卖」→ **不进 M1**，直接转 M2。

---

## 3. 关键设计点

### 3.1 城市必须显式确认，不许猜

`city` 是必填项，而学生说「我们学校」通常不带城市。处理顺序：

1. 上下文已有 `city` → 直接复用，不再问。
2. 用户的话里能推断出城市（如「我在南大仙林校区」）→ 用推断值，并**回述确认**：「按南京来查」。
3. 推断不出 → **一句话反问**：「你在哪个城市？」

不要凭关键词硬猜，猜错会导致整条链路的门店都错。

### 3.2 距离排序：用真实距离（已实测）

**实测结论（2026-10-20）：`query-nearby-stores` 返回值含 `distance` 字段，整数、单位为米**
（实测样本：811 / 998 / 1150 / 1234 / 1235）。

- 按 `distance` 升序排列，直接展示真实米数；超过 1000 米可换算为 km（如「1.15 km」）。
- 最近的一家标「最近」。
- 兜底：若某次调用异常返回不含 `distance`，退回按接口顺序 + 相对表述「最近 / 次近」，
  **严禁编造**距离数字。
- 注意：该结论仅适用于 `query-nearby-stores`；**`delivery-query-stores` 的返回不含距离字段**，
  外送门店排序只能按接口返回顺序。

### 3.3 得来速场景务必取回 beCode

`beType=5` 时接口返回的门店带 `beCode`，后续所有调用必须带上。
`beType=1` 时返回的门店无 `beCode`，后续**一律不传**（传了报错）。

### 3.4 预约时段的处理

若返回门店标记 `reservation=true`，展示 `reservationTimeOptions`，
其中 `today=true` 的项标注「（今天）」，供用户预约到店自取。

---

## 4. 上下文写入

用户选定门店后写入：

```
scene      = 到店自取 | 得来速
beType     = 1 | 5
orderType  = 1
city       = <城市>
storeCode  = <选定门店的 storeCode>
beCode     = <beType=5 时为门店的 beCode；beType=1 时为 null>
```

---

## 5. 输出

按 `references/output-templates.md` 的「门店雷达卡片」渲染。要点：

- 最多列 3 家，超出折叠。
- 最近的一家打「最近」标记。
- 有活动时附上 2-3 个活动名。
- 结尾给下一步：到店自取 / 切外送。

---

## 6. 异常与降级

| 情况 | 处理 |
|---|---|
| 无搜索结果 | 引导补充更具体地标：「试试说『XX 大学南门』，或者告诉我附近的路名」 |
| 关键词太泛（如只说「大学城」） | 同样引导具体化，不要返回一堆不相关门店 |
| 接口报错 | 复查 city 与 keyword 是否为空；若为 beType 相关错误，确认取值是 1 或 5 |
| 用户本来想外送 | 直接转 M2，不要在这条链路上耗 |

---

## 7. 与其他模块的衔接

- 用户选定到店门店后说「我要点单」→ 直接用本链路的上下文调 `query-meals(orderType=1)`。
- 用户反悔说「还是送宿舍吧」→ 保留 `city`，转 M2 重新按地址取门店与 beCode。
- 用户问「这家店有啥活动」→ 调 `campaign-calendar`，活动是全国/月度维度，不按门店区分。
