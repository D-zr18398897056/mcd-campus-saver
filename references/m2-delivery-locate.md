# M2 外送自动定位

把宿舍地址落进系统，拿到该地址可配送的门店与 beCode，之后整个会话自动携带，不再重复询问。

---

## 1. 输入

| 输入项 | 是否必需 | 说明 |
|---|---|---|
| 宿舍位置 | 是 | 口语表达，如「桂园 5 舍 302」「7 号楼 B 座 512」 |
| 外卖类型 | 是 | 普通麦乐送 → beType=2；多人拼餐 → beType=6 |
| 联系人信息 | 新建地址时必需 | 姓名、性别、手机号 |

---

## 2. 工具链

```
① delivery-query-addresses()          // 无参数
   → 返回已有地址列表，取 addressId
   ├─ 用户选已有的 → 直接拿到 addressId，跳到 ③
   └─ 用户要新增 / 列表为空 → 进 ②

② delivery-create-address(
     city          = <真实城市名>,      // 必填，如「南京市」
     contactName   = <姓名>,           // 必填
     gender        = 先生 | 女士,       // 必填
     phone         = <11 位纯数字>,     // 必填，如 18616646686
     address       = <楼栋>,           // 必填，如「XX 大学 7 号宿舍楼」
     addressDetail = <门牌>,           // 必填，如「B 座 512 寝室」
   )
   → 返回新地址的 addressId

③ delivery-query-stores(
     addressId = <上一步的 addressId>,  // 必填
     beType    = 2 | 6                 // 必填，2=麦乐送，6=团餐
   )
   → 返回可配送门店，取 storeCode + beCode
```

**注意**：`delivery-query-stores` 是外送专用。到店场景用 `query-nearby-stores`，两者不要混用。

---

## 3. 关键设计点

### 3.1 「自动定位」的真正含义

不是每次都问地址，而是 **首次问一次，之后整个会话自动携带**。

具体做法：
- M1 已经问过城市 → M2 直接复用 `city`，只补楼栋和门牌。
- 地址选定后写入 `addressId`，后续 `create-order` 自动带上，不再问。
- 用户中途换宿舍 → 只更新 addressId，并重取 storeCode/beCode，city 保留。

### 3.2 校园口语 → 接口格式的翻译

| 用户说 | address | addressDetail |
|---|---|---|
| 桂园 5 舍 302 | XX 大学桂园 5 舍 | 302 室 |
| 7 号楼 B 座 512 | XX 大学 7 号宿舍楼 | B 座 512 寝室 |
| 南区 3 栋 | XX 大学南区 3 栋 | （引导补充门牌号） |

门牌号缺失时**引导补充**，不要拿楼栋号填空。

### 3.3 手机号与城市名的校验

- `phone`：必须 11 位纯数字、1 开头。不满足就**反问**，不要尝试修正（别自作主张补位或删空格）。
- `city`：必须是真实城市全称（如「南京市」），不接受简称推断。
- `gender`：可从称呼推断（「张先生」→ 先生），推断不出就直接问。

### 3.4 beType 在此刻就决定，且会变化

这一步就决定了后面是普通外卖还是团餐拼单，且 **beCode 随 beType 变化**。

```
场景：用户先在 beType=2 下拿到 beCode_1
      然后说「我们 5 个人拼」
      → 必须重新调用 delivery-query-stores(addressId, beType=6)
      → 拿到 beCode_2，后续用 beCode_2
      → 不要拿 beCode_1 去调团餐接口
```

### 3.5 团餐场景的额外引导

`beType=6` 时，拿到地址后应立即引导用户提供**人数和预算**，
因为团餐必须有这两个值才能进入 M3 的方案生成。

---

## 4. 上下文写入

```
scene      = 麦乐送 | 团餐
beType     = 2 | 6
orderType  = 2
addressId  = <选定/新建的地址 ID>
storeCode  = <可配送门店的 storeCode>
beCode     = <同次返回的 beCode>
```

**外送场景不写 takeWayCode**，也禁止后续传给任何工具。

---

## 5. 输出

按 `references/output-templates.md` 的「外送定位卡片」渲染。要点：

- 确认配送地址（回述完整地址让用户核对）。
- 列出该地址可配送的门店，标注最近的一家。
- 团餐场景额外提示「宿舍拼单直接说人数和预算」。

---

## 6. 异常与降级

| 情况 | 处理 |
|---|---|
| 地址列表为空 | 直接引导新建，不要问「要不要新建」这种废话 |
| 手机号格式不对 | 反问正确的 11 位手机号，说明格式要求 |
| 该地址无可配送门店 | 说明超出配送范围，建议改用到店自取（转 M1） |
| 团餐门店不可用 | 降级为 beType=2 麦乐送，并明确告知用户 |
| 用户只说「送到宿舍」没给楼栋 | 反问具体楼栋，不要用学校名当地址 |

---

## 7. 与其他模块的衔接

- 拿到外送上下文后 → 用户说人数和预算 → 进 M3。
- 拿到外送上下文后 → 用户说「有啥优惠」→ 进 M4（注意 beType 可能是 2 或 6）。
- 用户要改地址 → 重新走 ①②③，并**清空旧的 storeCode/beCode**。
