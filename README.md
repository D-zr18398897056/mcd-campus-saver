# 麦麦校园省钱搭子（mcd-campus-saver）

> **一句话**：面向大学生的麦当劳省钱点餐助手——不只帮你下单，而是把「怎么买最划算」算清楚，包括凑单反差、券的真实可用性和 AA 分账金额。

---

## 背景

大学生的麦当劳消费有三个特点：**地点固定**（学校/宿舍周边那几家）、**多是拼单**（几个人一起点）、**预算敏感**（人均 30 块是常态）。但通用点餐助手解决不了这三件事：

1. **不知道你在哪** —— 学生说「我们学校附近有麦吗」，通用助手会反问一堆问题，或者凭关键词硬猜城市，猜错整条链路都白跑。
2. **不会算拼单** —— 「5 个人拼，预算 150」需要的是按人均档位生成方案 + 比价 + 分摊，不是把菜单念一遍。
3. **说不清券能不能用** —— 卡包里躺着 5 张券，通用助手直接说「你有 5 张券可用」，但真正下单时发现一张都用不了。

更麻烦的是，麦当劳 MCP 的 **参数链高度耦合**：`beType` 决定 `orderType`，`beType ≠ 1` 必须带 `beCode`，团餐还要 `gmServiceCode`，到店又要 `takeWayCode`——漏一个报错，多传一个（比如到店传 beCode）也报错。所以这个 Skill 的第一性设计不是四个功能，而是一套**会话上下文总线**：城市、地址、门店、业务编码只问一次，四个模块共享同一份状态，全程自动携带。

本 Skill 的规范不是纸上推演——四个模块全部经过真实接口联调，实测结论已回写到 `references/`，完整过程见 [SMOKE_TEST_REPORT.md](./SMOKE_TEST_REPORT.md)。

## 功能列表

### M1 校园门店雷达
输入学校名 / 校区 / 地标，输出附近麦当劳门店，**按接口返回的真实距离（米）升序排列**并标注最近的一家，同时挂上当天的营业时段与可预约时段。城市会先从上下文推断，推断不出才一句话反问，绝不硬猜。取餐方式由意图决定：走路/骑车 → 到店自取（beType=1），开车 → 得来速（beType=5）。

### M2 外送自动定位
把「我在桂园 5 舍 302」这类校园口语翻译成接口要求的地址格式，落库后拿到该地址可配送的门店与 beCode。地址列表为空时直接引导新建，不做「要不要新建」这种废话式确认。**「自动定位」的真正含义是首次问一次、之后整个会话自动携带**——不像通用对话那样反复追问。

### M3 多人拼餐计算器（核心亮点）
走**企业团餐（beType=6）**而非普通麦乐送，因为只有团餐场景能拿到满折规则、助餐服务和官方人均档位搭配规则。输入人数 + 预算，输出三套方案（省钱型 / 均衡型 / 凑单型），每套给出原价、实付、人均和内容清单，最后给 AA 分账金额。

关键设计是**凑单反差的诚实判断**：主动算「多买一件反而更便宜」，但**先看差额**——实测团餐折扣门槛是 300 元起（7.8 折），预算 150 时差 150 元，硬凑到 300 实付 ¥246，反而比不凑贵 ¥90。这种时候 Skill 会直接放弃 C 方案并说清楚原因，而不是编一个「凑单更划算」的假象。

### M4 学生优惠聚合
一键领券 → **验证这单到底能不能用** → 回流入计价算出省了多少。三条支线：券可用性筛选（以 `query-store-coupons` 为准，不以卡包为准）、活动日历（关键词筛出学生向活动，如麦金学期卡、早餐优惠）、积分兑换与体验活动。

两条硬规矩：券的可用性一律以门店级查询为准（实测团餐场景下可用券为空数组，卡包里的 5 张一张都用不了）；**抽奖必须先展示本次消耗并拿到明确确认**，严禁自动抽、连续抽。

## 安装方法

### 前置条件

- 已安装 [WorkBuddy](https://www.workbuddy.cn)（或其他支持 MCP + Skill 的 Agent 客户端）
- 已获取 mcd-mcp 的访问 Token

### 用法一：安装 Skill 文件

把本仓库的 `SKILL.md` 和 `references/` 整个目录放进 WorkBuddy 的 skills 目录：

```bash
# 用户级（所有项目可用，推荐）
~/.workbuddy/skills/mcd-campus-saver/

# 或项目级（仅当前工作区可用）
<your-workspace>/.workbuddy/skills/mcd-campus-saver/
```

放好后的结构：

```
~/.workbuddy/skills/mcd-campus-saver/
├── SKILL.md
└── references/
    ├── context-protocol.md
    ├── m1-campus-radar.md
    ├── m2-delivery-locate.md
    ├── m3-group-meal.md
    ├── m4-student-deals.md
    └── output-templates.md
```

`SKILL.md` 只放路由表、参数矩阵和易错点清单，四个模块的完整流程放在 `references/` 里按需加载——这样既不撑爆上下文，又保证每个模块有完整的调用规范。

### 用法二：配置 mcd-mcp 连接器

令牌通过环境变量注入，不要把 Token 明文写进提交到仓库的配置里。

**第一步：设置环境变量**

```bash
# macOS / Linux（写入 ~/.zshrc 或 ~/.bashrc 后需 source）
export MCD_MCP_TOKEN="你的令牌"

# Windows PowerShell（用户级持久化）
[Environment]::SetEnvironmentVariable("MCD_MCP_TOKEN", "你的令牌", "User")
```

**第二步：写入 MCP 配置**

仓库根目录提供了 `mcp-config.example.json`，把其中 `${MCD_MCP_TOKEN}` 占位符替换后合并进 WorkBuddy 的 MCP 配置文件 `~/.workbuddy/mcp.json`（注意不是 `.mcp.json`）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      },
      "disabled": false
    }
  }
}
```

如果 `mcp.json` 里已经有其他 Server，把 `mcd-mcp` 这一段合并进 `mcpServers` 对象即可，不要覆盖已有配置。

**第三步：启用连接器**

写入配置后 MCP **不会自动激活**。打开 WorkBuddy 的连接器管理页面，在右上角自定义连接器入口找到 `mcd-mcp`，点「信任」启用，然后重启客户端。

## 使用示例

以下三个例子全部来自 2026-10-20 的真实联调，数据是接口返回的真实数据，不是构造的。

### 示例一：查学校附近的门店

**你说**：「我在广州大学城，附近有麦当劳吗」

**Skill 调用**：`now-time-info` → `query-nearby-stores(searchType=2, city=广州市, keyword=广州大学城, beType=1)`

**它返回**：

```
📍 离你最近的 3 家麦当劳

1. 【最近】麦当劳广州广工西生活区餐厅 · 大学城外环西路100号 · 811 米
2. 麦当劳广州番禺中环西路创信园餐厅 · 中环西路7号 · 998 米
3. 麦当劳广州药科大生活区餐厅 · 大学城外环东路280号 · 1.15 km

（另 2 家已折叠：华南理工餐厅 1234 米 / 中环东路创投园餐厅 1235 米）

现在 00:26，这几家都还没开门（07:00 起）。

👉 回复「到店自取」直接点，或说「送到宿舍」切外送
```

距离是接口 `distance` 字段的真实值（单位米），不是估算。5 家门店全部落在小谷围街大学城范围内，「大学城」这类泛关键词的召回没有问题。

### 示例二：5 个人拼，预算 150

**你说**：「送到宿舍」→「5 个人拼，预算 150」

**Skill 调用**：`delivery-create-address` → `delivery-query-stores(beType=6)`（重取 beCode）→ `query-meal-assistance` → `query-promotions` → `query-meals` → `calculate-price` × 3

**它返回**：

```
👥 5 人拼 · 预算 150 · 人均 30

方案 A 省钱型   ¥152.30 → 实付 ¥149.00   人均 ¥29.80   ✅ 最省，唯一不超预算
  双层吉士汉堡×5 + 中薯条×1

方案 B 均衡型   ¥158.50 → 实付 ¥156.00   人均 ¥31.20   超预算 6 块
  双层吉士汉堡×5 + 可口可乐中杯×2

方案 C 凑单型   ¥319.50 → 满 300 打 7.8 折 → ¥246.00   人均 ¥49.20
  双层吉士汉堡×5 + 可口可乐中杯×5 + 中薯条×5 + 香芋派×5

⚠️ 说实话：团餐的折扣门槛是 300 元起（7.8 折），150 块够不着，
   A / B 省下的 3.3 / 2.5 元只是打包费减免，不是餐品折扣。
   这次没有「多买反而更便宜」——C 凑到 300 才打折，实付还是比 B 高 90 块。

💡 就选 A：¥149.00，卡在预算内，人均 ¥29.80
💰 AA 一下：5 个人每人 ¥29.80，整除不用抢尾差

👉 回复「下单 A」继续
```

注意这段里最值钱的不是三个数字，而是那句「够不着」——它来自 `calculate-price` 返回的 `enjoyable.balance`（还差 16000 分 = 160 元到门槛），是接口给的，不是猜的。

### 示例三：领券

**你说**：「有什么优惠，帮我领券」

**Skill 调用**：`available-coupons` → `auto-bind-coupons` → `campaign-calendar` → `query-store-coupons`

**它返回**：

```
🎫 一键领券完成，共领到 5 张
   这单（团餐）能用 0 张

✅ 领到的券
  · 11.9元麦辣鸡腿堡
  · 免费脆薯饼
  · 人气麦旋风买一送一
  · 9.9元中杯冰美式
  · 19.9元王牌炸鸡任选2

⏸️ 团餐这单用不了（query-store-coupons 返回空）
   团餐场景不支持这类麦麦省券，改走麦乐送(beType=2)再试

📅 本月学生党活动
  · 学生专属！49元150天麦金学期卡   ← 0.33 元/天，最划算的一张卡
  · 超值9.9元早餐两件套   10/8 - 10/21   还剩 2 天
  · 厚松饼堡早餐         10/8 起        早餐卡 6 折，3 件套 15 元起

👉 说「改麦乐送」我按能用券的场景重算一遍
```

「领到 5 张、这单能用 0 张」看起来是个坏消息，但它避免了用户在结算页才发现券用不了的挫败——这正是本 Skill 和普通领券助手的分界线。

## 目标用户

**主要用户：在校大学生。** 尤其是这几类场景里的人：

- **宿舍拼单组织者**：要算人均、要 AA、要在有限预算里尽量多拿东西，最需要 M3。
- **刚入学的新生**：对学校周边不熟，说不出具体地标，需要 M1 用「大学城」这种泛关键词也能召回。
- **预算敏感型用户**：会为了省 3 块钱多走 500 米，会认真看活动日历，需要 M4 的诚实筛选而不是一堆用不了的券。
- **深夜赶 due 的人**：凌晨下单时助餐服务可选范围会变（实测 GMS002/GMS003 仅 07:00–20:00 送达可用），需要 Skill 自动避开不可选项而不是报错。

**次要用户**：校园社团活动组织者（团餐场景天然适合 10 人以上拼单）、以及任何想验证「MCP 参数强耦合场景下 Agent 能不能稳定跑通」的开发者。

## 设计原则

三条贯穿整个 Skill 的硬规矩：

1. **禁止编造。** 拿不到距离、价格、券 ID、订单号就直说拿不到，绝不填充看似合理的值。
2. **诚实优先于推销。** 凑单反差不成立时不硬推 C，券用不了时直接说用不了。省钱的说服力来自准确，不是来自话术。
3. **高风险操作必须确认。** 抽奖前必须展示本次消耗并拿到明确确认，禁止自动抽、连续抽。
